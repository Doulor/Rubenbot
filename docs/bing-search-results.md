# Bing 搜索渠道实测与对比

日期：2026-11-23（北京时间 18:20–18:30） · 分支 `feat/bingsearch`
本文件只给数据，最终 `search.order` 由协调者定。

## 环境与方法

- **运行位置**：家里云（`ssh -F ~/.ssh/config homecloud`，公网直连）。本开发沙箱到 `cn.bing.com`
  的 TLS 握手在 10 秒内超时（`curl` 能通、`httpx` 不能，属本机出网限制），所以所有真实请求都在家里云发起。
- **代码**：本分支 `rubenbot/search.py` 原样上传到家里云临时目录，用
  `uv run --no-project --with httpx --with pyyaml python` 跑；没有部署、没有改线上配置。
- **计时口径**：进程内 `WebSearcher.lookup()` 从发起到返回的墙钟时间（含 HTTP + HTML 解析），
  每个渠道先各跑一轮预热连接，再采集数据；测量时 `cooldown_seconds=0`。
- **问题**：同一组 5 个问题，bing 与 tavily 背靠背各跑一遍；每个渠道取 5 条，记录前 3 条。
- **Tavily key 来源**：家里云线上 `~/rubenbot-test/config.yaml` 的 `search.tavily` 段，仅在本进程内存里读取，
  未打印、未写文件、未写日志。DeepSeek 渠道线上无 key，未测。

| Python 3.13 有什么新特性 | 0.168 | 0.172 | 0.311 |
| 英伟达最新财报怎么样 | 0.156 | 0.188 | 0.313 |
| 上海今天天气怎么样 | 0.161 | 0.189 | 0.302 |
| Linux 最新稳定内核版本是多少 | 0.164 | 0.158 | 0.307 |

- bing 冷启动首个请求约 0.75 秒，之后 0.15–0.2 秒；单个 `curl` 直测 `cn.bing.com` 稳定 0.34–0.45 秒。
- tavily 冷启动首个请求偶发 10 秒级（有一次超过 10 秒超时、返回「搜索暂时不可用」），预热后 0.3 秒左右。
- 「关键词式」与「原句」是同一批问题换检索词：原句直接把整句丢给 Bing；关键词式分别用
  `LPR 报价 2026年11月`、`Python 3.13 新特性`、`英伟达 财报`、`上海天气`、`Linux 内核 最新版本`
  ——正是 `web_search` 工具描述里要求的「几个具体的关键词」形态。两组分开跑的，延迟列各自独立。

## 结论与限制（只给数据）

1. **延迟**：bing 预热后 0.15–0.2 秒，比 tavily 的 0.3 秒快一倍；冷启动两者都可能到秒级，
   bing 冷启动 0.75 秒、最坏未见 10 秒；tavily 本轮出现过一次 10 秒级超时。
2. **检索词形态决定成败**：bing 对整句问句抓得很松（只命中「2026年」「上海」这类词），
   关键词式检索词则质量很好（5 题里 4 题前 3 条直接可用）。现有 `web_search` 工具描述已要求模型
   「只摘关键词」，但模型偶尔仍会交整句；这是 bing 渠道的固有短板，代码层不做改写。
3. **「无结果」不可靠**：`zzqxvbnm 不存在的东西 1937` 这类查询，Bing 没给「没有相关结果」页，
   而是返回 3 条超星登录页之类的无关结果。回退链只按「解析为空」顺延，无法识别「有结果但不相关」。
4. **索引**：`cn.bing.com` 是国内索引，中文站点覆盖好；官网页、百科、新闻都有。摘要为页面原文片段，
   个别摘要混入页面导航文字。
5. **链接**：解析出的都是结果直链（`h2 > a[href]` 的绝对地址），不是 Bing 的跳转包装；
   站内相对链接的条目已丢弃（没有可打开的原文，对查证无用）。
6. **页面结构**：本轮抓取的 5 份真实 SERP 都能解析出 10 条；改版/验证页/空结果页都按「空结果」
   交给回退链（单测覆盖）。`cn.bing.com` 在本沙箱返回 301 → `www.bing.com`，代码带
   `follow_redirects=True`，家里云上无跳转、直出 200。
7. **未测**：DeepSeek 渠道（线上无 key）；bing 在真实聊天轮里由模型自主选择并走完抓页→摘录整链
   （本轮只验证到 `lookup()` 返回结构化结果）。
