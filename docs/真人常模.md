# 从聊天流水测真人常模

在仓库根目录运行，只需 Python 标准库。推荐用同一时间段、同一群的**完整 SQLite 备份**，而不是两侧分别挑选的精彩发言。工具以 `mode=ro` 查询 `raw_messages`，不加载 bot、不调模型；路径写错会报错，不会创建数据库。

```sh
python3 tools/measure_liveliness.py sample.db > report.json
python3 tools/measure_liveliness.py sample.db --text
```

`report.json` 的 `sessions` 保留每个会话原有的消息形态与 bot 密度指标；`summary` 把各会话样本汇总，`conclusion` 是同一份中文结论。`--text` 可单独打印结论。两侧身份依流水约定：`__bot__` 是本 bot，其余 `__` 前缀为系统/工具记录，排除。外部自动账号若冒用普通用户身份，不能从这些字段识别，基线会受影响。

| 指标 | 两侧共同口径 |
| --- | --- |
| 消息长度 | 去首尾空白，计 Unicode 字符数，报告线性插值的 p50/p90/p95。 |
| 连发率 | 同会话、同一发送者、相邻且间隔 ≤4 秒；大小至少为 2 的连发组内消息数 / 连续流水消息数。两个人接话不算连发。 |
| 语气词率 | 一条消息中至少出现词表中一个语气字即计一次；词表见 JSON 的 `metric_definitions`。这是字面命中，不是语义判断。 |
| 回复间隔 | **换人发言**与同会话上一条消息的间隔，单位秒；首条及自己接自己均排除。无显式回复关系时只是接话速度的代理指标。 |
| 词汇重复度 | 每人每会话各自维护最近 50 个 token；已在窗口出现的 token 数 / token 总数。同一句里的重复也计入。中文取重叠双字（孤字保留），英文数字按词并转小写，忽略标点及 emoji。固定窗口避免长语料仅因样本多而天然更「重复」。 |

汇总按实际消息、间隔或 token 数加权；换群会切断邻接和词汇窗口。长度和间隔用两条经验累计分布之间的最大差（KS 距离）比较，另外三项是是/否事件，同一距离等于发生率差的绝对值。五项统一在 0–1 上排名：0 表示未测出差异，1 表示样本完全分开。缺少任一侧样本的指标不排名；并列最远一并列出。这是描述性差异，不是显著性检验，也不能据此推断「更像真人」。请结合样本数及分群结果阅读：长间隔可能只是大家睡了。

## 离线 JSON 与验证

```sh
python3 tools/measure_liveliness.py --corpus human_group.json bot_with_context.json --text
python3 -m pytest tests/test_measure_liveliness.py
```

平铺 JSON 数组每项至少有 `sender_id`、`text`、`ts`（Unix 秒）；可带 `id`（同时间戳排序）、`platform`、`chat_type` 和 `chat_id`。同平台同号的群聊与私聊分别统计；没有 `chat_type` 的旧数据按群聊处理。未给会话标识时用文件名区分。平铺格式按**连续流水**解释。抽样导出 `[{"bot": {...}, "context_before": [...]}]` 只统计 `bot` 消息，不把重复的上下文当新消息；抽样目标之间的真实邻接关系未知，不计算它们的连发率、接话间隔和密度。它们的词汇窗口只代表可见样本。需要完整五项时请使用完整流水，而非从抽样间隔猜回复耗时。

测试在临时目录生成独立 SQLite 样本，运行 JSON 和中文两种输出，并核对原库未改写；无需线上数据。
