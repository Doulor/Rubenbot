# 链接解析

群里有人发视频后问「这个视频讲了什么？」，bot 可以用公开的标题、UP 主、简介、时长接话；网页则参考标题、描述和正文摘录。插件不会发预览卡片，不会替 bot 决定开口，也不会把网页内容写进聊天流水或记忆。没有字幕或视频内容时，不会从视频画面生成摘要。

## 启用和触发

插件默认关闭。在 WebUI 的插件页启用「链接解析」，或将 `link_parse` 加入 `plugins.enabled`。用配置页修改参数，或把 `config.example.yaml` 复制为同目录的 `config.yaml`。修改后重新启用插件或重启 bot。

- `on_mention`（默认）：群聊和私聊仅在要回复、且本轮被 @、叫名字、回复 bot，或有提问/总结等请求时解析。只转发链接不会抓取。当前消息优先；没带 URL 时可引用带链接的消息，或明确追问「刚才那个链接是什么？」（只看同一会话近五分钟内最近八条消息）。
- `auto`：即使 bot 没有开口，也在收到链接时预取；要回复时只用已取得的资料，不补抓。`cooldown_seconds` 按平台、群/私聊和会话分别冷却，`daily_limit` 是整个插件按本地自然日计算的尝试次数。缓存命中不占额度，失败也算一次；0 次表示不新抓。
- 每条消息最多取三个不同的 HTTP(S) 链接；同 URL 的并发请求合并。`cache_ttl_seconds` 控制成功结果缓存（最多 256 条；0 关闭复用）。缓存与额度都是内存状态，重启或停用后再启用会重置。

## 资料来源和网络边界

`sites` 是启用列表。`bilibili` 读取视频页公开元数据或内嵌视频信息，支持 `b23.tv`；`generic` 优先读 Open Graph、`article` / `main` 正文或可见段落，正文不适合提取时只用标题或摘要。不执行 JavaScript，不打开页面引用的子资源，不尝试登录。删掉一个站点类别后，跳转也不能绕过；清空列表则不抓取。

出口按 httpx 的环境代理和 `NO_PROXY` 选择。每一跳都只连接已校验的公网 IP（HTTPS 仍按原域名验签），最多五次重定向；不传 Cookie 或站点凭据。HTTP(S) 代理需支持向目标 IP 建 CONNECT 隧道；代理不支持时不回退直连。站点仍会看到抓取方或出口代理的地址，不建议自动抓取含私密令牌的分享链接。

默认 `max_bytes` 为 1 MiB，`timeout_seconds` 为 6 秒（含 DNS、全部重定向和读正文）。非 HTML、压缩响应、不可达、超时或超限都按普通消息处理。注入时只有固定的隔离说明使用系统角色，网页字段单独标为不可信外部资料，不作为模型指令。
