# RSS 订阅

订阅网站的 RSS/Atom，定时抓新文章，用 QQ 合并转发推到指定的群或私聊。
默认关闭，机主在 WebUI 插件页启用。

## 指令（`/rss`）

私聊里任何人都能用；群里只有群管理员能订阅/取消/手动检查该群，列表人人能看。

```
/rss 订阅 <链接> [群号] —— 订阅 RSS，推到当前会话或指定群
/rss 取消 <链接> [群号] —— 取消订阅
/rss 列表 —— 看当前会话的订阅
/rss 检查 —— 立刻检查一次
```

- 私聊 `/rss 订阅 <链接>`：推到当前私聊。
- 私聊 `/rss 订阅 <链接> <群号>`：推到指定群（私聊不验群管理员）。
- 群里 `/rss 订阅 <链接>`：推到本群（仅管理员）。
- 订阅时先抓一次验证源：抓不到或解析不出条目会回「这个源抓不到」，不建订阅。
- 首次订阅不推旧文章：水位直接设到最新一条，只推之后新出的。

## 推送

- 一轮里一个源的新文章包成**一条合并转发**，一个节点一篇：标题 + 全文（纯文本）+ 链接。
- 单条新文章也走合并转发，保持一致。
- 全文里的 HTML 会洗成纯文本（去标签、去脚本，只留正文）。
- 每轮每源最多推 5 条（可配），超了只推最新的几条，剩下的不再补推。
- 单源抓取超时 15 秒；连续失败 5 次后在列表里标出（订阅保留，恢复后自动续推）。
- 轮询间隔默认 30 分钟：新文章发布后最多等半小时才推到群/私聊，不是立刻到。

## 提醒前缀

每条订阅（源 + 目标）可以单独设一个提醒前缀：有新文章时，先给同一目标发一条纯文本提醒，再发合并转发。留空就不发提醒。

- 占位符：`{rss}`=网站名称（源标题）、`{count}`=本轮新文章数、`{url}`=订阅地址；不认识的占位符原样保留。
- 例子：`{rss}发新帖子了`、`{rss}有 {count} 篇新文章`。
- 提醒发失败不影响转发：只记一条 warning，转发照发、水位照推。
- 设置位置：WebUI 插件详情页，每条订阅行里有个输入框，填好点保存（回车也行）；新增订阅时也可以直接填。

订阅列表在 WebUI 插件详情页里按订阅源分组管理：每个源一张卡片，源名和地址只写一次，下面列出所有订阅了该源的群/私聊；每行能改提醒前缀、能删除；顶部有新增订阅表单（地址、目标类型、目标号码、可选提醒前缀）。也可以用 `/rss 取消` 删。

## 实现说明

- 解析用 `feedparser`（RSS 2.0 / Atom / RDF）。
- 抓取走 core 的 SSRF 守卫入口 `fetch_public_page`，不另写 fetcher。
- 订阅表是独立 SQLite（`data/plugin_data/rss.sqlite3`），不写宿主存储。
- 合并转发走适配器的 `call_action`（`send_group_forward_msg` /
  `send_private_forward_msg`，OneBot 11 标准动作），已在网关目录
  `rubenbot/gateway/catalogs/snowluma.json` 里注册。
- 轮询是后台 asyncio 任务，插件停用时停掉，不留后台进程。
